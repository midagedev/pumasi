# 대시보드 — `pumasi up` 이 같이 띄우는 웹 화면

따로 설치하거나 빌드하는 것이 없다. controller 가 이미 여는 loopback 상태 주소에서 한 페이지를 낸다(`pumasi up` 이 시작할 때 주소를 한 줄 찍고, `pumasi open` 이 브라우저로 연다). controller 가 다른 호스트에 있으면 `ssh -L` 로 본다. 밖으로 열지 않는다.

## 화면 하나, 위에서 아래로

| 절 | 보여 주는 것 | 답하는 질문 |
|---|---|---|
| 문제 | 열린 사건([robustness.md](robustness.md)). 없으면 절이 없다 | 지금 손봐야 할 것이 있나 |
| 호스트 | 호스트마다 한 줄: 상한 대비 cpu·메모리 막대, cpu 압력, 러너 수, 상태(ok·unreachable·quarantined) | 어디가 찼나, 어디가 아픈가 |
| 러너 | 지금 떠 있는 러너: 클래스·호스트·상태·잡·경과·cpu·메모리(상한 대비) | 무엇이 돌고 있나 |
| 대기 | 기다리는 잡과 사유 한 줄, 기다린 시간 | 왜 안 뜨나 |
| 최근 잡 | 끝난 잡 50개: 결과·대기 시간·실행 시간·cpu 초·메모리 peak·호스트. 행을 누르면 그 잡의 결정 이력과 러너 로그 끝부분 | 느렸나, 왜 실패했나(코드인가 인프라인가) |
| 추이 | 24시간: 호스트별 사용 cpu, 대기 잡 수, 대기 시간 중앙값 | 상한·클래스 크기를 바꿔야 하나 |

## 만드는 방식

- 정적 파일 3개(html·css·js)를 `go:embed`. 프레임워크·번들러·외부 CDN 없음. 차트는 inline SVG.
- 데이터는 `GET /api/state`(지금 `status --json` 과 같은 것) + `GET /api/jobs` + `GET /api/series`. 5초마다 다시 읽는다. 장부가 유일한 출처라 controller 를 다시 켜도 이력이 남는다.
- 읽기 전용으로 시작한다. 조작(호스트 비우기, 격리 해제)은 CLI 에 먼저 넣고 화면에는 그 뒤에.
- 모양: 밝은 바탕, 표 중심, 장식 없음. 색은 상태에만 쓴다(문제 = 빨강, 대기 = 호박, 나머지 회색 글자). `pumasi status` 의 표와 같은 열·같은 낱말을 쓴다.

## Prometheus

controller 도 `/metrics` 를 낸다(에이전트 것을 모아 호스트 라벨을 붙인다). 이미 Grafana 가 있는 곳은 그쪽을 쓰면 되고, 대시보드는 그것 없이도 충분해야 한다.
